# 4.0 beta release preparation plan

> Execute in this session with the verification-before-completion workflow. The user authorized release preparation and publishing a new beta; website changes and deployment are excluded.

**Goal:** Publish the next numbered 4.0 beta with the five fixes after beta.16, accurate release notes, and an evidence-backed testing handoff.

**Architecture:** Keep the application changes already merged on main. Add release documentation, validate the final commit through the existing CI, and use Nightly Beta and Release workflows to build and publish it.

**Tech stack:** Electron, Jest, GitHub Actions, Markdown.

**Spec:** User request of October 8, 2026; `docs/RELEASE-4.0-AUDIT.md` and `docs/FEATURE-AUDIT-4.0.md`.

## Constraints

- Do not edit or deploy the website.
- Do not claim real-device or two-computer testing from mocks.
- Keep stable 4.0.0 undated and 3.x supported until stable publication.
- Keep package metadata at 4.0.0 on main; the beta workflow aligns build metadata from the tag.
- Do not touch the user's production configuration or credentials.

## Tasks

- [x] Verify the existing fixes with the full Jest suite, lint, CSS lint, repository hygiene, dependency audit, renderer/panel builds, and an isolated local startup check if supported.
- [x] Add beta.17 notes and a testing record, update the stable summary with the five fixes, and link the record from the release audit. Validate formatting, note extraction, and release tests.
- [ ] Review the documentation changes, merge the preparation after successful CI, verify main CI, dispatch Nightly Beta, and verify the published prerelease and its assets.

## Review focus

Release notes must describe actual changes, beta metadata must remain distinct from stable metadata, evidence must name its tested commit and environment, unavailable hardware checks must stay open, and the website hold must remain explicit.

## Decisions

- Stable dating and the security support switch remain release-day actions. Doing them for a beta would incorrectly announce stable availability and retire 3.x support early.
- The privacy review covers source behavior only. Maintainer approval and deployed hosting behavior remain part of the held website work.
