# User-facing audit, September 10, 2026

The audit of commit `0ed25c9` found eight user-facing defects. All eight are addressed in `3.11.0-beta.1`.

1. Queued cover and light slider commands could run after Stop or Turn Off. Direct actions now cancel incompatible pending commands in dialogs and desktop pins. Older failed dialog requests cannot roll back newer controls.
2. Quick Access accepted more than twelve tiles but only displayed and updated the first twelve. It now renders and tracks every tile in the active view, using the existing scrolling container.
3. Thermostats with heating/cooling ranges had no setpoint controls. Shared capability detection now supports range targets, bounds and feature validation. Both dialogs and desktop pins send the low and high temperatures together. Open dialogs adapt when live state changes between single-target and range modes.
4. Fahrenheit climate values could be labeled Celsius. Unit selection now falls back to Home Assistant's configured temperature unit.
5. Date-only calendar events were interpreted as UTC timestamps. All-day dates now stay on their intended day, including across daylight-saving changes, and the exclusive end is displayed correctly.
6. Failed to-do requests appeared as empty lists. Dialogs now show a load error with Retry. Refresh retries do not repeat successful mutations.
7. Primary device cards were unreachable by keyboard. They now support focus, Enter/Space activation and Shift+Enter for details, preserving focus across live-state replacements. Quick Access also supports Shift+Enter.
8. Binary lights exposed unsupported brightness controls. Their dialogs now show only power controls and send no brightness parameter.

The regression cases live in [user-facing-regressions.test.js](../tests/unit/user-facing-regressions.test.js) and [climate-controls.test.js](../tests/unit/climate-controls.test.js). They exercise actual DOM controls and outgoing service payloads with mocked Home Assistant responses. The calendar cases should also be run with `TZ=America/St_Johns` to exercise dates west of UTC.

The initial audit passed all 1,494 existing tests, demonstrating why the new regression cases were needed. Isolated Electron checks reproduced the original failures and verified the corrected temperature display and range controls. The General Settings dialog was inspected at 500 × 600, and the new desktop-pin range controls were inspected at 168 × 148.

Home Assistant documents heat/cool ranges in its [climate integration](https://www.home-assistant.io/integrations/climate/) and date-only events with exclusive ends in its [calendar guidance](https://developers.home-assistant.io/blog/2023/03/28/calendar_best_practices/).

The audit used synthetic entities and did not send commands to live devices. Physical device behavior, OAuth browser round trips, external sync providers, and desktop placement across operating systems still require integration testing.
