# Omarchy audit fixes and verification

The eleven findings in [the original audit](OMARCHY-AUDIT-2026-09-14.md) have corresponding changes. This report distinguishes tests that ran from the hardware checks still needed before claiming broad compatibility. No release, AUR submission, or Omarchy contribution was published.

The [live-system follow-up](OMARCHY-LIVE-TESTS-2026-09-14.md) adds credential-store and connection-recovery checks, plus a fix for a renderer startup race found during those tests.

The helper now closes unrelated inherited descriptors before opening its own sockets. Repeated packaged restarts retained CDP access and restored the selected output.

## Test results

- Full JavaScript coverage suite: 83 suites, 1,633 tests passed; coverage thresholds passed.
- Rust: five protocol/control tests passed.
- ESLint, Stylelint, formatting, repository hygiene, renderer build, and Linux directory packaging passed.
- Native packaged script: layer creation, separate pins, capabilities, isolated startup, show/hide/toggle, live palettes, portal activation, selective elevation, and unchanged animation settings passed.
- Arch package: `ha-desktop-widget-bin-3.10.0-1-x86_64.pkg.tar.zst` built locally. The package contains a root-owned sandbox helper with mode 4755, the `/usr/bin/ha-desktop-widget` link, the canonical desktop entry, and MIT/GPL license files. The version remains the repository's existing build version; this is not a published update.

On the installed Omarchy system, using isolated profiles and private portal processes:

| Scenario                                                                              | Sample     | CPU as a percentage of one core |
| ------------------------------------------------------------------------------------- | ---------- | ------------------------------- |
| Audit baseline, visible and disconnected                                              | 30 seconds | about 13.8%                     |
| Fixed build, visible and disconnected                                                 | 30 seconds | 0.22%                           |
| Fixed build, explicitly hidden                                                        | 30 seconds | 0.27%                           |
| Fixed build, connected to a synthetic local HA server with temperature and lamp tiles | 30 seconds | 0.33%                           |

These are observations, not a controlled performance benchmark. The fixed-build measurements include the disposable portal processes. The connected test used invented entities and a test token; it did not contact or control the user's Home Assistant installation.

## Limits and release checks

The native run used Hyprland 0.56.2, Electron 43.1.0, xdg-desktop-portal 1.22.1, and xdg-desktop-portal-hyprland 1.4.1 on the installed Omarchy desktop. Real monitors were tested at scale 1.

A nested compositor's virtual output failed GPU-buffer allocation and reported zero dimensions. Chromium then hit its empty-window-geometry check. That run does not establish virtual-output compatibility; it prompted the new zero-size protocol guard. The subsequent native desktop runs used valid outputs.

Before proposing default inclusion, still test physical hot-unplug/replug, fractional scale and mixed-DPI displays, rapid pointer dragging with stock animations enabled, suspend/resume, and sustained camera/weather workloads on the supported GPU families. The original running widget had already disabled layer animations, so leaving those settings unchanged on that desktop does not establish animated-drag behavior. The new drag path avoids using the animated surface's relative coordinates, but its behavior under stock animations still needs that direct check.

The private D-Bus fixture did not provide an unlocked credential store. It therefore cannot verify first-login keyring unlocking or real credential persistence; existing credential tests passed, and no production credentials were read for these checks. Press the configured physical key combination as a final shortcut check: dispatching the portal target proves the integration path, not the absence of a conflict in a user's key map.

The user's running installation, desktop configuration, and Omarchy source files were not replaced. Test processes were stopped after verification. Build artifacts are in `dist/arch`; installation, publishing, and upstream submission remain separate steps.
